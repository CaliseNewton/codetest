# Assumptions
- **Plain bool merge (pinned, not yet confirmed as intended):** `MergeEvent` always takes `Hidden` from the right operand, because a plain bool cannot tell "not sent" apart from `false`. So any update or transform delta that leaves `Hidden` out makes the event visible again. Both transforms copy `Hidden` from the full model into their deltas to avoid this, and clients must resend `Hidden` on every update. `TestMergeEvent_HiddenTakenFromRight` pins the current behaviour; revisit if partial updates should leave `Hidden` untouched.
- Racing event types are identified by `EventTypeID` values `horse_racing`, `greyhound_racing` and `harness_racing`.

# Decisions
- `GetRacingEvent` returns an empty response (no error) both when the event does not exist and when it exists but is not a race (`RacingData` is nil). This matches how `GetSportEvent` handles a missing event.
- `RacingData` is a plain field alongside `SportData` rather than a `oneof`. A `oneof` generates interface wrapper types in Go, which would make the hand-written merger much harder to follow.
- Runner level data (barrier, jockey, scratchings) was left out of scope for Task 2.
